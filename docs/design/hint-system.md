# 提示与纠错功能守则

本文记录提示系统整改中已经确认的经验和不可破坏的行为契约。修改关卡生成、求解器、提示 UI 或纠错功能时，应先检查本文并运行完整测试。

## 已发生的问题与教训

### 1. 数学唯一不等于玩家可以无猜完成

MiniZinc 证明的是题面不存在第二个数学解。它不能证明玩家按照当前提示规则一定能继续推进。

曾经的关卡生成器允许双线索集合差集，而默认提示只展示单个数字的直接结算。结果是关卡在高级规则下可解、MiniZinc 也证明唯一，但玩家按照默认提示会稳定停在 32/400。

守则：

- MiniZinc 只负责唯一性。
- `DirectClueSolver` 负责默认玩法是否能从空盘无猜完成。
- 生成与删减线索的每一次验收都必须使用 `DirectClueSolver`。
- `NoGuessSolver` 的差集能力只用于高级难度研究，不能代替默认提示规则的验收。

### 2. 提示必须对应一个玩家能看懂的局部事实

默认提示只能选择一个题面已有的数字：

- 该数字格强高亮。
- 它在同一区域内、经边界裁剪后的最多 3×3 范围弱高亮。
- 该数字根据当前玩家盘面必须已经满足“剩余亮格为 0”或“剩余亮格等于未知格数”。
- 提示每次都必须从玩家当前落子重新计算，不能重放预生成答案步骤。

### 3. 提示不应改变棋盘布局

曾经在棋盘上方动态插入完整推理卡片，点击提示后会把棋盘整体向下推，持续干扰页面布局。

守则：

- 不得在棋盘上方重新加入随提示出现/消失的大段说明面板。
- 提示反馈只使用棋盘强弱高亮，以及页面已有的固定状态文字区域。
- 不得因提示触发自动滚动到动态说明块。

## “清除错误答案”契约

公开关卡 JSON 继续隐藏目标答案。页面加载后，`deriveDirectSolution` 仅使用公开数字和区域规则重建唯一答案，供纠错按钮使用。

点击“清除错误答案”时：

- 与推导答案不同的亮格或暗格恢复为未知。
- 与答案一致的玩家标记必须保留。
- 原本未知的格子必须保持未知。
- 一次点击清除当前盘面的全部错误标记。
- 操作结束后清除旧提示高亮，重新分析并渲染当前盘面。
- 若无法从公开线索重建完整答案，按钮应禁用；不得猜测或部分清理。

实现中的 `clearIncorrectValues` 必须保持为无副作用的纯函数，不直接修改传入的玩家数组。

## 防回归测试

以下测试是功能契约的一部分，不应为适配错误实现而删除：

- 真实公开关卡能仅靠网页默认提示从 0 推进到 400 格。
- 页面不存在会撑开布局的 `boardHintSummary`。
- “清除错误答案”是操作区中的固定按钮，而不是棋盘浮层或动态面板。
- 浏览器能够从公开线索推导完整 400 格答案。
- 纠错只删除错误标记，并保留正确标记、未知格和输入数组本身。

运行：

```powershell
npm test
```

## 修改前检查表

- 生成器与默认提示是否仍使用同一套基础规则？
- MiniZinc 唯一性与默认无猜验证是否仍然分开？
- 提示是否明确指向一个数字及其同区域有效范围？
- 点击提示是否保持棋盘位置和页面高度稳定？
- 清除错误是否只删除错误标记？
- 公开关卡是否仍不包含隐藏答案？
- 完整测试是否通过？
