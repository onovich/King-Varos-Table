# 按需图片优化 — 2026-09-08

本轮采用无损 WebP 替换 28 张 PNG：26 张概念图与参考图、1 张历史 UI 截图、1 张宴厅海图。保留原始尺寸、透明像素与 ICC 配置；逐张比对 RGBA SHA-256，解码后的像素完全一致。

| 范围 | 优化前 | 优化后 | 节省 |
| --- | ---: | ---: | ---: |
| 28 张 PNG | 69,057,708 字节 | 47,595,416 字节 | 21,462,292 字节（31.1%） |
| 运行时海图 | 3,357,384 字节 | 2,314,094 字节 | 1,043,290 字节（31.1%） |

已有 JPG 截图约 29–230 KiB/张，不做再次有损编码。木材与扫描食物的 2K 颜色、法线、粗糙度、ARM 贴图保持原样；不改变近景材质、glTF 标准或模型依赖。没有付费服务、LFS 迁移或 Git 历史重写。

所有现有文档图片引用和运行时海图引用同步更新。原始 PNG 已在提交 `d6568b6cd49bc482fc2dd2dc2ae863be73d079db` 中备份，可从 Git 恢复；当前目录避免重复保存两套图片。这减少当前资源体积与海图下载量，不减少 GPU 纹理占用，也不会移除已推送的历史二进制对象。新增格式首次推送仍需上传，后续只有修改的对象需要传输。

## 重现与校验

工具需要 Pillow（本机验证版本 12.3.0，含 WebP 支持），不影响游戏运行依赖：

```sh
python tools/optimize_review_images.py          # 只试算有收益的 PNG
python tools/optimize_review_images.py --apply  # 至少节省 15% 才替换，并更新引用
python tools/optimize_review_images.py --check  # 比对清单记录的原始尺寸与 RGBA 哈希
```

逐文件尺寸、字节数、原始提交和像素校验值见 [清单](image-optimization.json)。完整 80 项 unittest 通过，git diff --check 通过；浏览器加载独立宴厅正常。原图和 WebP 像素校验全部通过。
