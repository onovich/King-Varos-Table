# 序章与关卡册架构

状态：已实现并验收  
完成日期：2026-08-29

## 目标

在不复制解题页面的前提下，把单张 20×20 原型扩展为可继续增长的战役入口：新玩家先通过三张短教学页理解直接推理、国界裁剪和多国地图，再进入“内海七国”正式版图；每张棋盘独立保存，完成一页才解锁下一页。

## 玩家流程

1. `序页一 · 第一盏灯`：6×6、单一区域，教授亮格、暗格、0 与满数规则。
2. `序页二 · 国界以内`：8×8、两个国家，教授粗国界如何裁剪数字范围，并明确提示的强／弱高亮含义。
3. `序页三 · 三国小图`：10×10、三个国家，教授区域筛选、必然步骤、检查和错误清理。
4. `内海七国`：20×20、七个国家，进入晚宴、亡国故事卡、档案和后世尾声的正式叙事循环。

完成教学页后会出现固定尺寸的完成对话框。玩家可直接继续下一页，也可打开关卡册。正式地图仍按“完成国家—弹出亡国卡—收入档案”的既有节奏运行，不额外插入教学完成框。

## 数据边界

- `web/data/campaign.json` 只负责章节、顺序、关卡入口、显示摘要和 `unlockAfter` 依赖。
- `web/data/levels/*.json` 各自保存棋盘、区域、线索、双语关卡文本和可选的教学／叙事字段。
- 清单与关卡通过稳定的 `id` / `levelId` 对应；载入时不一致会拒绝该关卡。
- 公开 JSON 不含目标答案。浏览器端从线索重建完整答案，仅用于安全地清除错误标记。
- `npm run generate` 同时重建清单、三张教学关和正式地图；所有区域必须通过直接推理，并由 MiniZinc 排除第二解。

## 存档与解锁

- 关卡册进度和单张棋盘进度使用不同的本地存储命名空间。
- 关卡册只保存已完成关卡 ID 与最近进入的关卡；未知、重复或跳过前置依赖的完成记录会被清理。
- 每张棋盘继续使用带版本号和内容指纹的独立存档，因此切换关卡不会覆盖其他棋盘。
- 已完成关卡可以从关卡册重玩；重置棋盘不会撤销关卡册中的完成记录，也不会重新锁住后续关卡。
- URL 使用 `?level=<id>` 记录当前页。只有已经解锁的 ID 才会被采用，锁定或未知 ID 会安全回退到下一张可玩关卡。

## 界面守则

- 关卡册始终位于页眉，显示 `已完成数 / 总数`；锁定关卡可见但不可操作，并有明确文字状态，不能只靠颜色表达。
- 教学说明占用规则栏中的固定区域；正式地图隐藏该区域，恢复晚宴和档案入口。
- 小棋盘在桌面端限制最大宽度，不拉伸成巨型格子；20×20 地图保持原有密度。
- 320px 窄屏下，页眉标题与工具分行，棋盘只在自己的边框内横向滚动，页面本身不得横向溢出。
- 切换关卡后滚回页面顶部；语言切换、刷新和跨关卡返回均不得丢失进度。

## 验收结果

- 四张关卡均可由浏览器直接提示规则从空盘推到底。
- 三张教学关和正式七国地图的每个区域均通过 MiniZinc 唯一性验证。
- 浏览器实测走通首次进入、错误清理、提示范围、三次解锁、正式地图切换、双语切换和刷新续存。
- 320px、768px 与桌面宽度没有页面级横向溢出；浏览器控制台没有警告或错误。
- 自动化测试共 36 项。

## 后续扩展

新增章节时优先增加新的清单章节和独立关卡文件，不在 `app.js` 中增加按章节复制的页面分支。难度分级器现已按求解轨迹为清单提供 `tutorial`、`standard`、`advanced` 标签，契约见 [difficulty-grading.md](difficulty-grading.md)；它不得改变提示系统“只展示单个可直接结算数字”的玩家契约。
