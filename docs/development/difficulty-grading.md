# 关卡难度分级契约

状态：已实现并验收<br>
完成日期：2026-08-30

## 目标

让难度标签来自可复查的求解轨迹，而不是关卡清单里的手工判断；同时把“是否需要高级规则”和“需要做多少工作”分开，避免把大棋盘直接误称为高级推理。

## 核心术语

- **格子赋值（assignment）**：求解器确定一个格子的亮暗。旧版 `solverSteps` 统计的是这个数量，因此完整求解时几乎总等于区域格数。
- **线索结算（deduction）**：玩家根据同一个数字或同一个派生约束，一次确定一个或多个格子。这才对应一次“必然步骤”。
- **推理级别（reasoning level）**：`basic` 只使用可见单数字的 0／满数规则；`advanced` 至少使用一次重叠线索差集。
- **工作量（effort）**：按全关线索结算数分为 `short`（不超过 15）、`medium`（16—40）与 `long`（41 以上）。它描述流程长度，不冒充经过真人校准的认知难度。

## 自动标签规则

优先级固定如下：

1. 任何区域出现高级差集结算，整关标记为 `advanced`；
2. 否则，教学关标记为 `tutorial`；
3. 其余只靠可见数字直推的正式关标记为 `standard`。

因此，即使一张关卡被放进教学章节，只要其求解轨迹需要差集，也必须显示为高级，不能被章节用途掩盖。若要声称“高级规则是必需的”，应先证明 `DirectClueSolver` 停滞，再由 `NoGuessSolver` 使用差集完成。

## 公开指标

每个区域记录：

- 可见线索密度；
- 格子赋值数与线索结算数；
- 第一次、最小、最大和平均每次可确定格数；
- 只能确定一个格子的结算次数；
- 基础与高级结算次数；
- 最终推理级别。

整关汇总还记录区域数、总格数、最长单区域结算链和工作量。`firstForcedCells` 现已恢复其字面意义，不再错误地等于整区格数。

## 生成与消费边界

- `varos_table.difficulty` 是无 UI 依赖的公开评估 API。
- 教学关和正式关生成器都把区域及整关指标写入公开关卡 JSON。
- `tools/generate_campaign.py` 从整关分析结果复制关卡册标签，不再写死 `tutorial` 或 `standard`。
- 浏览器关卡册只接受 `tutorial`、`standard`、`advanced` 三种生成标签；缺失或未知值会拒绝载入。
- `npm run report:difficulty` 会从公开线索重新运行直推求解器；直推停滞时再运行高级无猜求解器，并把重算结果与关卡档案、清单标签逐项比较。它还会拒绝关卡目录中未登记的 JSON，因而可以发现陈旧档案、清单漂移和漏登记文件。

## 防误用

- 难度分析不能替代 MiniZinc 的唯一解证明。
- `basic` 不表示关卡短，`long` 也不表示需要高级规则。
- 工作量阈值是当前内容生产基线；有试玩数据后可以调整，但调整必须同步更新测试与本文。
- 默认提示仍只展示单个可见数字可以直接结算的范围。高级差集关卡在正式加入战役前，必须另行定义可理解的玩家提示契约。
