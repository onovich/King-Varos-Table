# 触屏与键盘操作

状态：已实现并验收<br>
完成日期：2026-08-29

## 目标

让同一张棋盘在鼠标、触屏和纯键盘环境下都能完成，不要求触屏玩家模拟右键，也不让键盘玩家用 Tab 穿过数百个格子。

## 玩家契约

- 棋盘上方固定提供亮格、暗格、擦除三种落笔工具；点击或轻触格子使用当前工具。
- 棋盘格继续只以底色表达亮、暗、未知，不叠加会遮挡数字的符号。
- 重复使用亮格或暗格工具涂同一状态，会把该格恢复为未知；擦除工具始终恢复未知。
- 右键与 Shift+点击继续直接标记暗格，保留原有桌面操作。
- 棋盘获得焦点后，`1`、`2`、`3` 分别选择并使用亮格、暗格、擦除；`Delete`、`Backspace`、`0` 可直接擦除。`Enter` 与空格使用当前工具。
- 方向键按二维位置移动；`Home` / `End` 到当前行首尾，配合 Ctrl 或 Command 时到整盘首尾。
- 棋盘使用 roving tabindex，Tab 只进入棋盘一次。已完成国家仍可被键盘和读屏软件查看，但标记操作不再生效。

## 界面约束

- 320px 窄屏下，三种工具必须同时可见且保持可点击尺寸；工具栏在棋盘滚动期间保持粘性。
- 页面本身不得横向溢出；大棋盘继续只在自己的深色边框内横向滚动。
- 工具状态不能只靠颜色表达：当前工具同时使用 `aria-pressed` 和反色外观。
- 中英文必须拥有同一组工具、规则说明和无障碍名称。

## 代码边界

- `web/input-tools.mjs` 只负责把工具、指针和按键转换为格子状态或二维目标位置，不依赖 DOM。
- `web/app.js` 负责工具栏、roving tabindex、棋盘事件与既有存档流程的连接。
- `tests/test_input_tools.py` 从公开输入函数和页面无障碍 DOM 两个边界防止回归。

## 验收结果

- 模块测试覆盖三种工具、旧右键兼容、状态切换、二维边界和键盘快捷键。
- 浏览器实测键盘暗格、方向键移动、亮格、擦除，以及点击工具后的触屏式落笔；测试结束后格子恢复未知。
- 320px 实测无页面级横向溢出，三按钮各自保持 78px 宽，棋盘在边框内部滚动，工具栏为粘性定位。
- 浏览器控制台无警告或错误。

## 暂不包含

- 拖动连续涂色、长按手势与触觉反馈；
- 撤销／重做历史；
- 用户自定义快捷键。
