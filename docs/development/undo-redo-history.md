# 撤销／重做历史契约

状态：已实现并验收<br>
完成日期：2026-08-29

## 目标

让玩家能够安全撤销落笔、错误清理和重新开局，并保证跨越“国家完成—故事归档”节点时，棋盘与叙事不会彼此脱节。

## 玩家契约

- 棋盘工具栏提供 `撤销` 与 `重做`；同时支持 Ctrl/Command+Z、Ctrl+Y 和 Ctrl/Command+Shift+Z。
- 历史最多保存 100 个会话内步骤。切换关卡或刷新页面后，以已保存的当前局面作为新历史起点。
- 每次单格落笔是一项操作；一次“清除错误答案”或“重新开局”整体算作一项操作。
- 撤销后产生新操作时，原重做分支立即丢弃。
- 任意模态窗口（包括故事、尾声、完成提示、档案和关卡册）打开时禁用全局历史快捷键，避免玩家在弹窗背后改变棋盘。

## 原子快照

每一项历史必须同时包含：

- 全部格子的亮、暗、未知状态；
- 已完成国家；
- 已归档故事；
- 待展示故事队列；
- 尾声是否已归档。

不能只记录格子。否则撤销国家的最后一格后，格子会恢复而国家仍被锁定；反向错误则会重复弹出已经读过的故事。

故事卡关闭后的“已归档”变化会替换当前快照，而不会额外制造一个看不见的撤销步骤。因此，玩家撤销的是导致国家陷落的最后一次落笔；重做后，该国与已经归档的故事一起恢复，故事卡不会重复弹出。

## 持久化边界

- 历史栈本身只存在于当前页面会话，不写入本地存储。
- 每次撤销或重做后的当前局面仍照常写入逐关存档；刷新后从该局面继续。
- 关卡册的“已经完成／已经解锁”是长期战役记录，不随棋盘撤销而回锁。这与重新游玩已完成关卡时仍保留解锁一致。
- 语言、当前国家筛选、提示高亮、当前落笔工具和焦点不属于棋盘历史。

## 代码边界

- `web/board-history.mjs` 是无 DOM 的不可变历史模块，负责复制快照、容量上限、分支和前后移动。
- `web/app.js` 负责把棋盘与叙事状态装入快照、恢复界面、持久化当前结果以及管理快捷键。
- `tests/test_board_history.py` 从公开模块与页面无障碍 DOM 两个边界防止回归。

## 验收结果

- 自动化测试覆盖原子恢复、快照所有权、100 步容量机制、当前快照替换和分叉后清空重做。
- 浏览器实测普通落笔、按钮与快捷键、焦点保持、教学页完成、正式国家陷落、故事归档和弹窗期间的快捷键隔离。
- 正式国家在撤销后恢复为 32/33 格且取消完成与归档；重做后恢复为 33/33 格并保留已归档状态，不重复弹故事卡。
- 320px 视口下两个历史按钮同排显示，页面无横向溢出；浏览器控制台无警告或错误。
